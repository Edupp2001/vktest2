# Weather Test Task

![Weather Script CI](https://github.com/Edupp2001/vktest2/actions/workflows/weather.yml/badge.svg)

Решение тестового задания на Python.

## Описание задачи
Скрипт считывает список городов из файла, получает текущую погоду для каждого уникального города через API `wttr.in`, выводит данные по каждому городу, а затем группирует их по странам и вычисляет статистику (среднюю, минимальную и максимальную температуру).


## Требования
- Python 3.10+
- Используются **только стандартные библиотеки** Python: `json`, `urllib`, `dataclasses`, `collections`.

## Структура проекта
- `Cities.txt` — файл со списком городов (в корне проекта).
- `PythonApplication3/PythonApplication3.py` — основной скрипт.
- `.github/workflows/weather.yml` — конфигурация CI/CD для GitHub Actions.

## Запуск локально
1. Клонируйте репозиторий.
2. Убедитесь, что в корне проекта лежит файл `Cities.txt`.
3. Перейдите в папку с исходным кодом:
   ```bash
   cd PythonApplication3
4. Запустите скрипт
   python PythonApplication3.py

## Почему настроен CI (GitHub Actions)?

В процессе локального тестирования скрипта возникла непредвиденная проблема: интернет-провайдер блокировал или сильно замедлял запросы к бесплатному API `wttr.in`. Из-за этого при локальном запуске скрипт стабильно получал ошибки таймаута (`The read operation timed out`).

Чтобы подтвердить корректность логики кода и предоставить проверяющему гарантированно работающий способ запуска, было принято решение настроить пайплайн CI/CD на GitHub Actions.

**Преимущества такого подхода:**
*   **Обход сетевых ограничений:** Серверы GitHub (Ubuntu) имеют стабильный и прямой доступ к внешним API, что позволяет обойти локальные блокировки провайдера.
*   **Автоматизация проверки:** Скрипт автоматически запускается при каждом пуше в ветку `main`, что гарантирует, что код всегда находится в рабочем состоянии (зеленый бейдж CI).
*   **Демонстрация навыков:** Показывает умение настраивать CI/CD, работать с YAML-конфигурациями и изолировать окружение для запуска.
*   **Ручной запуск:** Проверяющий может запустить скрипт в один клик через вкладку **Actions** -> **Weather Script CI** -> **Run workflow**, не настраивая окружение локально.

*Пример успешного вывода в CI подтверждает, что код полностью соответствует требованиям задания.*
